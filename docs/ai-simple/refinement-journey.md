## 覆盖边界

流程使用真实 `createFinanceDeskStore`、本地仓库序列化/重载、内存 fileVault、`createAiFinanceService`、银行 CSV 解析/导入、凭证和报表核心，并由 `runFinanceAssistant` 经真实 `requestDeepSeek` 完成工具回合。客户端与代理函数之间使用进程内请求适配，不启动 HTTP 服务；只有 DeepSeek 外部 fetch 返回预置响应。没有替换业务工具、存储动作、财务结果或原件校验。

| 场景 | 可抓住的模块接缝问题 |
| --- | --- |
| 空白工作台与操作人 → 原件上传 → 错误列映射 → 人工修订 → 重载 → 导入 | 余额列 975/960 修正为发生额 -25/-15；新预览、实际导入金额一致；旧建议失效；同建议并发/重复确认以及再次准备同一原件均不重复导入 |
| 真实已导入流水 → AI 业务建议 → 人工确认 → 原件复核 → 入账和报表 | 建议阶段没有凭证，确认后仅草稿；移除原件会阻止入账，恢复同一原件后才可入账；费用25元、利润-25元、现金流-25元，另一笔未入账15元不混入报表；保留流水/凭证来源 |
| 本地保存的票据原件及识别结果 → 读取 → 字段建议 → 人工修改 → 重载确认 | 修改金额及单位名称后重新预览，未修改候选字段保留；确认前业务字段不变，确认后原件字节/哈希不变，也不会把发票查验状态改成已查验或自动入账 |
| 上传取消与助手错误/取消后的继续 | 第二份文件保存前取消保留第一份，重传不复制原件；缺少账户返回可恢复工具结果，再由模型修正；供应商断连后建议保留；取消工具批次保留已完成项、补齐可继续的对话记录；重载继续不重放人工确认 |
| 外部回复返回时切换工作台 | 旧服务立即停止工具和确认写入，新台无资料/流水/凭证，旧台原件及建议仍在 |

成功结果、异常消息、工具记录、发给模型的正文以及序列化财务数据均断言不含测试传输密钥。密钥仅为固定假值，不读取环境凭据，不发真实网络请求。

票据场景直接保存已知正文及识别产物，是“已有本地识别结果进入建议流程”的输入夹具，不声称实际执行 OCR/PDF。原件缺失场景通过内存 fileVault 的真实删除/恢复操作注入状态变化，没有绕过校验。首笔费用以零期初的测试台验证本期发生额，不代表期初建账或期末归档验收。
